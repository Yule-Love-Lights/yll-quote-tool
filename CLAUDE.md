## Running scorecard (cumulative — skim before starting work)

**Keep doing (these worked):**
- Branch off **FRESH `origin/master`**, never the worktree's stale base — first confirm the spec/plan commits are actually present (mine weren't until I rebased).
- Re-ground the exact lines before planning, **then independently verify the recon** — a fast read-agent missed a real data leak and cited a stale file; my own grep caught both.
- TDD + run all three gates (`tsc · lint · vitest`) **after every phase**, not just at the end.
- Run the adversarial review before merge — and **disposition** each finding (fix / accept-as-parity / process). Don't blindly "fix" a pattern that matches existing prod code.
- Verify safety before an irreversible prod op (grepped for bare-anon data paths before enabling RLS; smoke-tested the live app after).
- Surface the high-risk / council-worthy / shared-file calls and confirm outward-facing actions instead of rubber-stamping.
- **[S18] Verify UI in the ACTUAL browser** — tsc-green ≠ correct. A client/server import-boundary break (#52 dragged the server-only `sharp` chain into the client bundle) and a HIGH `/training/new` railing ship-blocker BOTH passed tsc (an `as` cast laundered the type) and surfaced only in-browser + in the adversarial review. **[S19 reinforced 3×]** — Jason's device rounds caught a tag-expansion leak, a garland-trace gap, and a strip-placement miss, all invisible to tsc/tests.
- **[S19] Checkpoint cadence for epics** — slice a big feature into 2-PR chunks → dev device-verifies → merge bottom-up → next chunk. Beat both "one giant PR" and "gate every PR" on #13 (6 PRs, 3 checkpoints, feedback reshaped each next slice; stacks never grew past 2 branches; relays only on approved editor-core).
- **[S19] Scope a big epic with a recon workflow BEFORE the plan** — the 6-agent #13 recon + completeness critic caught the `maybeSingle()` silent-empty-materials trap (killed the N-designs architecture before any code) and 5 wrong claims via cross-verification.
- **[S19] Mechanical prompt/text moves → prove byte-identity** — extracting shared blocks out of the quoting SYSTEM_PROMPT via a substring-move script + an eval-and-compare check made "the prod prompt didn't change" a fact, not a hope.
- **[S20] Model-routing policy pays — Sonnet builds, Opus reviews/orchestrates (the seat), Fable only-if-asked.** The whole #110 fix marathon (~19 PRs) ran Sonnet-build/Opus-review — dramatically cheaper than S19's Opus builders, same quality, because the seat reviews every diff + integrates. Route deliberately, don't default everything to the top tier.
- **[S20] For a fix BATCH, integrate locally + gate the COMBINED tree BEFORE any merge — never-stale for parallel PRs.** Every wave's fixes were built by parallel worktree agents on disjoint files, then merged into one int branch, gated (tsc·eslint·vitest) as a set, and only then landed PR-by-PR with a real-master final gate. Caught composition issues a per-PR gate can't; the recurring `googleMaps.test.ts` two-agent conflict was resolved once, cleanly.
- **[S20] Write a workflow script to a FILE + `node --check` before launching.** A W4 workflow died on a missing `)` in a `.map()`; a W5 workflow was fine. The habit: Write the script, `node --check` (top-level `return` is the only expected "error"), then `Workflow({scriptPath})`. Cheaper than a failed launch.
- **[S20] Audit-workflow shape that worked 6×:** dimension finders (per sub-area × lens) → semantic dedupe → **adversarial verify every finding** (refute-lens for bugs, real-at-this-scale for perf, payoff-lens for refactors) → completeness critic. Pre-load intentional-design context so finders don't "discover" deliberate behavior as bugs. Dedupe against a seeded known-findings ledger so waves don't re-report #80.

- **[S23] When the task's premise contradicts prod reality, verify the live system FIRST and surface the discrepancy — don't act on the premise.** The task said permanent was "DORMANT behind `permanentEnabled` (OFF)"; a read of prod `app_settings` showed it already ON, and a grep proved the flag had ZERO consumers (inert — the real gate is the quote's `service_type`). Reading ground truth turned "flip the flag" into "delete the dead flag" and caught that "dormant" never held. The task text is a hypothesis, not the state.
- **[S23] For a customer-facing go-live you can't drive live (no secrets/node_modules), an in-process E2E of the REAL modules + a seeded `is_test` prod quote substitutes.** Drove pricing→packages→$2,500-gate on a real house via `tsx` (front $2,480 · sides $2,765 · back $1,925 → $7,797.38, D===total no drift), then seeded a permanent `is_test` quote for the human's live-portal eyeball. Validated P4/P5/P6 without a browser.
- **[S23] The adversarial hunt finds the money bugs the happy path hides.** The 7-dim hunt's HIGH was a tax-override under-bill that only triggers on a PARTIAL approved selection (permanent per-side packages A/B/C make partial the DEFAULT) — invisible to the go-live E2E; two-lens verify (reachability + money) killed 6 false positives; the completeness critic flagged the BOM engine as dead code (= the P7 build). Seed the hunt with confirmed-intentional design so finders don't re-flag it.

**Fix going forward (mistakes I've made):**
- **[S23] Supabase MCP does DML fine — the "read-only" note is DDL/migrations ONLY.** Used `execute_sql` to read `app_settings`, DELETE the inert flag row, and INSERT a seeded test quote — all worked. Don't route data reads/writes through the browser SQL editor; only DDL (schema/migrations) needs it. (Corrects the S13 note above.)
- **[S23] A post-merge restarted branch needs `--force-with-lease` to push, and fast-moving master will stale a PR mid-review — re-merge + re-gate the combined tree before landing.** #378 went 23 commits stale (Jason's #379 event-flag removal, mirroring mine) between green and merge; merged master in, resolved a `serviceType`/`isPermanent` prop collision by consolidating onto the shared prop, re-gated (vitest 1607) before merging. "Never merge stale" bites even same-day.
- **[S20] A big parallel fan-out WILL occasionally hit a transient server-side rate-limit (not your quota) — resume from the journal, don't re-run.** W5's first run lost 10/14 finders to rate-limiting; a resume replayed the 4 cached + re-ran the 10, and because their findings feed dedupe/verify/critic those re-cascaded correctly (the partial 3-HIGH re-adjudicated to the accurate 1-HIGH on the full set). Don't trust a partial workflow result; resume for full coverage.
- **[S19] Expanding shared link data → audit every downstream consumer first.** The sceneLinks twin-expansion (right, for portal toggling) silently fed twin ids into the photo-tag chip lookup → canonical rows mis-tagged. When a shared structure gains members, grep its readers before shipping.
- **[S18] Widening a shared/analyzer type → grep EVERY consumer + stale narrow duplicate up front.** The railing detection type had two parallel narrow copies (`/training/new`, `QuoteBuilder`) hidden behind `as` casts that tsc didn't flag; only the review caught them. Before shipping a type widen, list every UI that displays/edits it.
- **[S13] Map PR dependencies FIRST.** Given a batch to merge, check base branches (`gh pr view <n> --json baseRefName`) before touching anything — I began merging a *stacked* PR (#229) out of order and had to abort + re-plan bottom-up (#227→#228→#229).
- **[S13] Trust the documented gotcha immediately.** The Supabase MCP is **read-only** (no DDL) — go straight to the Chrome SQL editor for migrations instead of trying `apply_migration` first and eating the error. (It's in `project_apply_migrations_via_browser.md`.)
- **[S13] Browser-tool quirks:** the Chrome `javascript_tool` REPL doesn't reliably await a long async loop (a Monaco poll returned `{}`) — use synchronous checks + explicit `wait`s. The Supabase SQL editor takes ~12–18s to mount Monaco; wait up front. And **batch browser actions** (`browser_batch`) instead of one screenshot/click/wait per call.
