## New confirmed findings

### 1. Booked amendments have no customer re-consent path

Severity: High

Files: `src/app/api/quotes/[id]/amend/route.ts:231`, `src/app/api/invoices/[id]/charge-balance/route.ts:30`, `src/lib/quoteStatus.ts:124`

Failure scenario:

- Start with a booked quote totaling $2,000.00 and a paid $1,000.00 deposit.
- Re-price it to $2,400.00 and record the amendment.
- The invoice balance becomes $1,400.00.
- Settlement returns `reconsent-required`.
- The quote remains booked. The portal is read-only. The approval state machine does not allow booked to approved.

Wrong output: The customer cannot review or sign the $400.00 increase. Staff can proceed only with an operator override.

Suggested fix: Add a pending-amendment consent record and portal comparison screen. Capture a new signature for the changed total. Let settlement consume that consent marker without changing the paid booking state.

### 2. The public approval endpoint accepts no signature

Severity: Medium

File: `src/app/api/quotes/[id]/approve/route.ts:180`

Failure scenario:

- Use a sent quote with a valid package and item selection.
- POST the normal approval body to `/api/quotes/{id}/approve`.
- Omit the `signature` field.

Wrong output: The route returns success, writes `approval_snapshot.signature = null`, and advances the quote to approved.

Suggested fix: Require a valid signature on the public customer route. Keep any legacy or staff approval exception behind a separate authenticated path.

### 3. Customer delivery failures still show as sent

Severity: Medium

Files: `src/app/api/quotes/[id]/send/route.ts:256`, `src/app/api/quotes/[id]/send/route.ts:491`, `src/components/quote/QuoteBuilder.tsx:2148`

Failure scenario:

- Send a real quote through both SMS and email.
- Make both HighLevel message calls fail.
- Let the pipeline update succeed or fail independently.

Wrong output: The quote is stamped sent. The API returns HTTP 200 with `ok: true`. The builder shows a sent state and ignores `smsSent`, `emailSent`, and `messageError`. The customer receives no link.

Suggested fix: Track local send state separately from delivery state. When every requested channel fails, return a delivery failure and show channel-specific retry controls.

### 4. Half-cent tax boundaries can round down

Severity: Low

Files: `src/lib/pricing/pricingEngine.ts:900`, `src/lib/portal/derivePackages.ts:148`

Failure scenario:

- Use a taxable subtotal of $1,002.80.
- Use the current 8.75% tax rate.
- Use no discount or fee.

Wrong output: The exact tax is $87.745. Binary floating-point represents it just below the half-cent boundary. The code returns $87.74 instead of $87.75. It returns a $1,090.54 total and a $545.27 deposit instead of $1,090.55 and $545.28.

Suggested fix: Calculate in integer cents with an explicit half-up rule, or use one decimal-money helper for the pricing engine and portal.

### 5. Quote-builder customer labels are not associated with inputs

Severity: Low

File: `src/components/quote/QuoteBuilder.tsx:2688`

Failure scenario:

Wrong output: The inputs have no accessible names from their labels, and clicking a label does not focus its input.

Suggested fix: Add matching `id` and `htmlFor` values, or wrap each input inside its label.

## How this tool works

An operator signs in and starts a quote in test or real mode. They choose a service vertical, add customer details, load a property image, and use AI analysis to seed a design. The design drives measured line items. The builder prices the scope, applies discounts and fees, calculates tax, splits the deposit, and lets staff choose recommended items.

The operator saves and sends the quote. The customer opens a public portal link. They can compare packages, toggle eligible items, see the live total and deposit, type their name as an e-signature, and approve. A test quote simulates the deposit. A real quote can enter the Valor payment flow. Paid deposits create the booked job. Completed work produces an invoice for the remaining balance.

The approval snapshot is the signed source for the selected package, item ids, total, deposit, and signature. Later amendments append to that snapshot. Invoice and settlement code use the latest agreed total and the actual deposit paid.
