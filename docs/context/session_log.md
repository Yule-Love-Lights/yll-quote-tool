### Session 3 — #17 Phase 2 (portal switch) + Phase 4 (AI red/blue tracing) (2026-06-03) · CURRENT
**Picked up from:** Session 2 close-out — #17 Phase 1+1b merged (engine mutually-exclusive Santa's/Gingerbread model + builder recommend radios). Did Phase 2 first (merged), then Jason chose to finish the roofline epic with Phase 4 in the same session.

**Shipped (PR `jason/roofline-phase2`, branched off `master`):**
- **#17 Phase 2 — portal roofline switch.** `/portal/[quoteId]` (Snowglobe) now PRESENTS BOTH roofline options (Santa's vs Gingerbread) and lets the customer pick one (mutually exclusive). **Design — Jason's call after a first iteration was rejected:** NO dedicated "Your roofline" selector. Both options are ORDINARY line items in "What's Included", behaving like every other item, with two layered behaviors: (1) only the staff-recommended option is selected by default; (2) clicking the other **deselects it** (you can only ever have one — never both); (3) clicking the selected one **removes it** (no roofline) — same gesture as toggling a tree/bush off, so there's **no separate Remove button**. **No roof footage/measurements on the customer portal**, and Gingerbread shows no "front + ridge + sides" subtitle.
- **How it's wired (all in `src/lib/portal` + `components/portal`):** the adapter (`buildPortalLineItems` in `adapter.ts`) reads `result.rooflineOptions`/`rooflineChoice` and REPLACES the single billed roofline line item with one line item PER captured option — `roofline-santas` (kind `roofline`) / `roofline-gingerbread` (kind `ridge`), no `detail`. New `PortalRoofline = { itemIds, recommendedItemId }` on `PortalQuote.roofline` tells `SelectionContext` the either/or group → `toggleItem` deletes the sibling roofline id(s) when ADDING one. Only the RECOMMENDED option is bundled into the A/B/C package tiers + counted toward the $1,000 gate: a `tierLineItems` filter in the adapter drops the non-recommended option before `derivePackages` + `minimumOrderSubtotal`, so a tier never selects two rooflines and the gate-waiver sum never double-counts (a quote whose two options sum ≥$1,000 but where neither alone clears it is correctly waived, not falsely gated). Switching/removing a roofline flips the package to "Build Your Own" exactly like any item toggle (Jason confirmed that's desired).
- **Backward-compatible:** quotes priced before Phase 1 (no `rooflineOptions`, or `rooflineChoice 'none'`) keep their single roofline as a plain toggle — `roofline` is undefined, the `isBilledRoofline` filter doesn't fire, nothing changes. Winter Wonderland (C9) is never mistaken for the roofline (matched by label, not the shared `ridge` kind).
- **Copy tweak (Jason):** What's-Included helper line no longer mentions "Build Your Own" → now *"Toggle anything off to remove it and we'll update your total automatically."*
- **Repo docs sync (folded into this PR as planned):** `docs/context/*` + `docs/CURRENT_STATE.md` were stale at #18 — brought current through **#4 + #17 Phase 1+1b + this Phase 2** (mirrored local memory; updated CURRENT_STATE's roofline/pricing section).

**Phase 2 ending state:** **Merged to `master`** (PR #13, 2026-06-03). Gates green (`tsc`, `lint`, **47** Vitest tests — 8 new in `adapter.test.ts`). 7 files: `types.ts`, `adapter.ts`, `SelectionContext.tsx`, `page.tsx`, `dark/WhatsIncluded.tsx` (copy only), `mockQuote.ts`, `adapter.test.ts`.

**Shipped — #17 Phase 4 (PR `jason/roofline-phase4`, branched off `master` after #13):** the LAST roofline phase. Three parts:
- **AI tracing reclassification (`src/lib/photoAnalysis.ts` SYSTEM_PROMPT).** Rewrote the roofline rules so the model classifies by which way each roof plane faces: 🔴 **Santa's (red) = the FRONT roofline only** — front-facing gutters/eaves + the rakes of a FRONT-facing gable; 🔵 **Gingerbread (blue) = the ridge + the SIDE runs** (side-facing gutters/eaves + side-gable rakes). **Confirmed terms with Jason:** a *gable* = the triangular wall under a pitched peak; a *rake* = its two diagonal edges. **FRONT-SECTION-ONLY rule (added after Jason's annotated test shots):** we measure ONLY the front section of the roof facing the road — NOT the full perimeter, and NEVER the back/backyard edge (~90% of jobs; rare whole-roof/backyard jobs are done manually). The satellite rule was the big fix — it had been tracing the whole perimeter AND mis-picking the front (it traced the edge facing a neighbor's driveway, not the road); now it must correlate with street view to find the REAL road and trace only the front section. **Downspout exclusion** added: never trace the vertical gutter pipes running DOWN a wall to the ground — only the horizontal roofline.
- **Builder + training labels (`quote/new`, `training/new`):** red → **"Front Gutterline"**, blue → **"Ridge + Sides"** (buttons "+ Add Front Gutterline" / "+ Add Ridge / Side", readouts "front … · ridge+sides …"). Cues operators to put side gutters on the blue line. (Jason confirmed these look good.)
- **"Gingerbread Ridge" → "Gingerbread" renames:** `rendering/variants.ts` (`VARIANT_LABELS`), `portal/variantPhoto.ts`, `dark/PackageVariantGallery.tsx` (+ blurb), `training/corrections/page.tsx`. **Kept the internal render-variant KEY `'ridge'`** (renaming it would touch stored render rows). The functional legacy shim in `adapter.ts` + the historical note in `lineItemKind.ts` intentionally still contain the literal "Gingerbread Ridge".

**Phase 4 ending state:** **In PR `jason/roofline-phase4`** (merge-all-now, Jason's call). Gates green (`tsc`, `lint`, 47 tests — no NEW tests; the change is prompt/label text, not unit-testable AI behavior). Labels + renames verified by Jason in his Chrome; the AI-tracing behavior **could NOT be cleanly verified** — see the blocker below. 7 files: `photoAnalysis.ts`, `quote/new/page.tsx`, `training/new/page.tsx`, `rendering/variants.ts`, `portal/variantPhoto.ts`, `dark/PackageVariantGallery.tsx`, `training/corrections/page.tsx`.
