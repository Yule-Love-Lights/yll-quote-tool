# Ledger number history

Every task-number collision this repo has had, and how each was adjudicated.

This was one continuous 25,160-character line at the top of `task_ledger.md` -
12% of that file, on the single line every session has to read to claim a
number. Moved here **verbatim** on 2026-08-29 (Jason S58); nothing was reworded,
summarised or dropped. The live counter and the rule stayed behind in
`task_ledger.md`.

Read this when a number is contested, not routinely.

The rules it paid for, so they do not have to be re-derived:

- The counter on master is **necessary and not sufficient**. Check the archive,
  every open PR, every unmerged branch, and the machine-local
  `feedback_self_assessment.md` before claiming a number.
- A **merged** row beats an unmerged claim, even one already cemented in source
  comments. Source anchoring only breaks a tie between two UNMERGED claims.
- A long-lived close PR should expect to renumber on every re-sync, so keep a
  row number in as few places as possible.
